Executive Summary

Overall status: usable, with significant defects. Core workflows work end to end against Dataverse: starting a handover, logging events, administrative issues, outages, patient-flow figures, DAMA cases and experience data, autosave, the report viewer, PDF export and draft deletion. Five HIGH issues need attention. AHJ users can't select OPD patients at all. Freshly saved drafts disappear from Home. Every user's Home lists every other user's drafts, with Delete buttons. Egyptian hospitals search a KSA-only ER patient source. The group dashboard shows hardcoded or always-zero metrics.

Critical / High Issues

DM-01 KSA OPD patient search always fails HIGH Measured / Reproduced

Area
Events / Administrative Issues, business unit AHJ, area "OPD KSA"
Steps
Open a draft for AHJ → Administrative Issues → Log administrative issue → Patient Area "OPD KSA" → type 2+ characters.
Expected
Matching KSA outpatients are listed.
Actual
The request GET opd_ksapatientses?$select=opd_ksapatientsid,opd_name,opd_patientcode,opd_patientname&$filter=contains(…) returns HTTP 400: Could not find a property named 'opd_name' on type 'Microsoft.Dynamics.CRM.opd_ksapatients'. The error is swallowed and the result list stays empty. Re-tested on its own with the same result.
User impact
Patient is mandatory, so AHJ users cannot log any event or administrative issue against an OPD patient. No error message is shown.
Root cause
opd_ksapatients has no opd_name column (its primary name is opd_newcolumn). searchPatients catches the error and returns [].
Code
src/duty/DutyManager.tsx:3559 (patientSchema OPD_KSA), :3563–3583 (searchPatients)
Fix
Remove opd_name (or use opd_newcolumn) in the OPD_KSA select. Show a visible error when a patient search fails.

DM-02 Newly saved drafts disappear from Home HIGH Measured / Reproduced

Steps
With more than 5 drafts in Dataverse, start a new report, then return to Home.
Expected
The new draft is listed first as "Current draft".
Actual
Local saves store timestamp as toLocaleString() ("10/27/2026, 5:02:19 PM"). Drafts restored from Dataverse use ISO ("2026-10-27T12:40:05Z"). getDrafts sorts with localeCompare, so the newest draft ranked 28th of 28. Home shows only 5, so it had no Continue or Delete button, and Home's "Active draft" and header pointed to a different draft. Every later save re-applies the locale format (reproduced twice).
User impact
Users cannot find the draft they are working on after leaving it. Readiness and completion on Home describe the wrong draft.
Code
src/duty/DutyManager.tsx:773 (writeDraft timestamp), src/duty/drafts.ts:39 (ISO timestamp), src/duty/utils.ts:88 (string sort), src/duty/DutyManager.tsx:1384 (top 5)
Fix
Store ISO timestamps everywhere and sort by Date. Show the user's own drafts first.

DM-03 Every user's drafts are restored to every user's Home HIGH Measured (listing) Code review (delete effect)

Steps
Sign in as any duty manager and open Home.
Expected
Only the signed-in user's drafts (or drafts they are allowed to take over) are listed.
Actual
The draft query filters only on status. A fresh browser restored 27 drafts (full bundles: report, flow, events, admin, ops, experience, DAMA, shortages) into localStorage: 11 belonged to the tester, 14 to six other duty managers, and 2 had no duty manager. The Unfinished Drafts list showed colleagues' drafts with Delete and Continue. Continue rewrote all of that draft's records (see DM-06). Delete removes the draft and all linked Dataverse records. Delete was verified only on the tester's own draft.
User impact
A duty manager can accidentally delete or overwrite another manager's in-progress handover. Each browser also downloads every draft on startup.
Code
src/duty/DutyManager.tsx:615–643 (filter at :618), :1006–1026 (deleteDraft), :1384
Fix
Filter by _dma_dutymanager_value eq <current systemuserid> (or a deliberate takeover rule), add $select, and enforce delete rights with Dataverse security roles.

Functional Issues

DM-08 Shift handling does not follow the business shifts MEDIUM Measured / Reproduced

Actual
  • Shift is a Dataverse choice (Morning 989230000, Evening 989230001, Night 989230002); no start or end times are stored.
  • The default shift for a new form comes from the local hour with boundaries 07:00 / 15:00 / 23:00; the business shifts are 08–14 / 14–20 / 20–08. So 07:00–08:00 defaults to Morning (should be Night), 14:00–15:00 to Morning (should be Evening), and 20:00–23:00 to Evening (should be Night).
  • "Start new report" instead picks the shift after the BU's latest submitted report, ignoring the clock. The existing SMH draft is "Night" at 15:24.
  • The test draft was saved as Night at 16:54 without any warning.
  • A read-only check of 306 reports found 217 whose shift label does not match the business shift for their recorded time. Many are test data, but nothing prevents it.
Code
src/duty/utils.ts:12–13, src/duty/DutyManager.tsx:713–769
Fix
Centralise the shift windows (08/14/20, Night crossing midnight). Derive the default from the clock and validate the report time against the selected shift.

Write amplification (DM-06)

Two effects watch broad dependency lists. Any change to the form or to admin issues PATCHes the report and the flow summary and re-syncs shortages (:542–554). Any change to events, admin, ops, DAMA or experience re-saves every experience, event, admin, ops and DAMA record (:556–566, autosaveSections :929–984). Creating a row then updates state with its new id, which triggers a second full cycle (:957).

Measured examples:

  • Adding one admin issue: 12 requests, 10 writes.
  • Adding one DAMA case: 10 writes.
  • Logging one outage: 10 writes.
  • Changing one Experience number: 7 writes.
  • Pressing "Continue" on a draft without editing: 7 writes.
Fix: track dirty records and write only those, and don't autosave on open.

Reusable test setup

The project has no documented way to test it end to end. This audit used tools that are not part of the repository:

  • playwright-core attached over CDP to a visible Edge started with --remote-debugging-port and a separate profile, so the user can sign in.
  • A small static server serving dist/ plus the plugin's __vite_powerapps_plugin__/power.config.json endpoint, to run the production build through Local Play.
  • Test-browser-only instrumentation that counts connector calls.
Turning these into a reusable "run and audit" skill would make future audits repeatable.
